01执行摘要

让用户在导出前选对格式，在导入后知道该检查什么。 Joplin 文档已经明确提供用于恢复的 JEX 和面向交换的 Markdown 路径。公开反馈提出了附件路径和导出结果说明的具体问题。优先建议是为这两种用途提供清楚的入口，随后为失败或无法验证的内容提供可定位的迁移摘要。[2] [13] [14]

四款产品的差异来自数据容器：Joplin 的备份包、思源的工作空间、Obsidian 的文件库、Logseq 的图谱。本文用相同任务对比它们的公开迁移路径，并用独立的评分矩阵标记公开证据覆盖范围。

02研究背景与目的

期末复习和毕业交接常要求把笔记连同目录、图片与附件一起保存。Markdown 让正文易读，但文件可读只是迁移的一部分。课程笔记能否继续使用，还取决于相对路径、附件引用、标签和应用特有结构是否得到保留。

研究任务 在 Windows 桌面场景，从现有笔记库取出一套资料，备份或迁入另一款工具，随后检查正文、目录、附件和关联内容。考察对象为个人本地笔记。云同步仅用于说明产品定位与付费模式。

03研究方法与数据来源

  1. 公开文件走查。以四方官方指南、官网和发布说明逐步核对入口、格式、备份及边界。检索日期为 2026 年 11 月 26 日。
  2. 公开平台证据。GitHub 主页抄录星标约数，只观察仓库关注度。Joplin 社区样本采用目的性抽样，保留四条与任务直接相关的讨论。
  3. 统一任务与启发式检查。按发现入口、选择格式、执行、验证结果四阶段逐项检查。文档提供的能力、官方图示观察、社区个案、设计推断分别标识。
  4. AI 辅助。用 AI 整理公开资料、归类反馈并生成矩阵草案，关键结论复核到原页面。此次没有招募受访者，操作时间、迁移成功率和保真率均为未知。

04目标产品概况

Joplin 是跨平台开源笔记工具，公开功能包括多媒体笔记、网页剪藏、Markdown 与富文本编辑，以及多个同步选项。个人笔记用户可使用本地客户端，团队共享与更便捷的托管同步由 Joplin Cloud 分档收费。迁移入口让用户从旧工具进入，也为本地资料的定期备份提供价值。[1] [2] [3]

06目标用户与需求分析

备考学生 · 搬走一个学期的资料

动机　换电脑或换工具后继续复习。
任务　搬走按科目分组的笔记、讲义 PDF 和截图。
障碍　不了解备份包和交换格式，容易以正文可读代替逐项验收。

研究型用户 · 保存可回溯的笔记库

动机　能长期检索、引用和重新利用资料。
任务　保留标签、跨笔记链接、来源文件及目录关系。
障碍　从块图谱或笔记本转到文件库时，结构转换需要额外核对。

两类画像为根据任务与社区反馈归纳的设计假设，用于界定需求和规划后续访谈。[10] [13] [15]

07产品功能架构分析

核心链路由内容管理、格式转换和复查组成。Joplin 的笔记本与笔记是操作对象，格式决定恢复和交换的范围。搜索与附件用于复查，网页剪藏与同步为辅助能力。思源以文档和块为组织单元，Obsidian 以文件库为载体，Logseq DB 以图谱为迁移对象。[1] [2] [4] [7] [10]

08信息架构分析

Joplin 把迁移命令集中在文件菜单。Obsidian 可经文件浏览器完成基础 Markdown 导入，也有面向 ZIP 与规范化设置的官方 Importer。思源公开指南把 Data 恢复放在桌面设置中。Logseq DB 的相关动作在图谱菜单。四者入口随被迁移对象而变化。[2] [4] [6] [10]

09用户流程分析

  1. 确认用途留在本应用恢复，或交给其他应用读取。
  2. 定位入口从文件菜单进入导出，记录选中的范围。
  3. 选择格式同应用备份用 JEX，跨应用交换核对 Markdown 方案。
  4. 导入副本在目标工具打开或导入，保留源资料。
  5. 验收结果复查笔记数、目录、图片、PDF、链接和标签。

流程图基于 Joplin 官方入口和本研究的验收步骤。迁移本身采用桌面文件路径，登录环节涉及可选的云服务。导入进行中、空包、重复导入及失败后的产品反馈在本轮均未实测。[2] [3]

10交互设计分析

格式选择

JEX 的用途和保留内容由官方文档解释。产品机会是把这层说明放到选择格式时，帮助用户用目的判断。菜单原貌及其说明可见性待实测。[2]

异常与控制权

思源 Data 文档明确警示同路径文件会被覆盖。Logseq 明示标准 Markdown 不含全部属性。Joplin 的导入前冲突提示、取消和重新导入行为仍需验证。[4] [10]

16产品差异化机会

功能层　借鉴思源导出参数按关联范围配置的思路，在 Joplin 明示资源与链接的保留范围。[17]

交互层　借鉴 Logseq 文档对标准 Markdown 的保真说明，把「备份恢复」与「跨应用交换」作为入口。文件夹直开的方式依赖 Obsidian 的存储模型，Joplin 可以借鉴其低门槛导入体验，通过拖放触发现有目录导入。[2] [6] [10]

视觉层　把结果做成可扫描的分组摘要，优先显示需处理项和所在笔记，次级区域展示成功数量与报告保存位置。[13]

18总结与研究局限

Joplin 已有本地备份与交换能力。优先让用户理解两种格式的适用目的和数据边界，再用迁移摘要缩短核对时间。四款工具的公开资料足以比较迁移路径，实际保真和易用性仍需在统一数据集上验证。

下一轮建议用 3 个目录、12 篇 Markdown、6 张图片、2 份 PDF 和跨笔记链接构建测试集。在四款 Windows 版本中记录版本号、警告、每类项目是否保留、完成时间和失败恢复步骤。Logseq DB 和文件图谱分别测试。建立基准后再判断产品排名与优化成效。
